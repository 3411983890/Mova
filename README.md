## ChatMova / CodeMova 开发状态

Windows 桌面版可启动，支持拖动、缩放、最小化、最大化、还原和关闭窗口。桌面和浏览器共用同一界面；窗口控制是首个迁移到 React / TypeScript 的区域。

Windows 桌面版的 ChatMova 和 CodeMova 使用 Pi Agent 处理模型回复和工具调用，默认模型为 `deepseek-v4.1-flash`。回复会流式显示并渲染 Markdown：标题、列表、引用、表格、行内代码、带语言标记的代码块（含复制按钮）以及经过允许列表检查的外部链接。模型原文中的 `**加粗**`、`*斜体*`、`` `代码` `` 等符号会转换为对应格式；不执行回复里的原始 HTML，也不加载远程图片。

回复失败、停止或中断后会显示「重新生成」，重试会保留旧尝试并重新请求当前模型；失败提示会区分鉴权、限流、超时、网络、模型权限与出口限制。长对话按 60,000 字符安全预算保留最近消息，较早内容只附加有限的原文摘录，完整记录不会因此删除；单条消息超过预算时会明确要求拆分，而不是静默截断。刷新后可从侧栏重新打开会话，刷新前未完成的回复会标记为「上次生成已中断」。

桌面聊天的「思考与操作」显示模型实际返回的思考、本条回复发出的每个搜索查询、读过的页面和可展开的网页来源；来源图标取自网站自己的 favicon（桌面后台抓取并缓存，取不到时回退到内置站点图标），思考展开后直接显示正文，不再有「查看原文」这一行。支持图片的模型可接收上传、粘贴或拖入的 PNG、JPEG、WebP、GIF 图片（最多 4 张，每张 4 MB），并在「读取图片」中查看。

对话页右上角的「⋯」打开「Token 用量」：本会话累计输入 / 输出、缓存命中、最近一次调用、最近一轮耗时、模型调用次数与花费，全部来自提供商返回的 usage。用量按会话累加，并随会话写进本地库（临时聊天除外），所以回复结束后和重启之后都还在；切换会话时跟着换，缺报的字段显示为「—」，未配置价格时显示「未配置价格」，不做估算。

多步骤任务会先立目标：模型通过 `set_goal` 发布目标、`accept_goal` 接受它，再用 `set_plan` 维护步骤。目标被接受后，每一轮回复结束都会自动检查——还没完成就自动开始下一轮（对话里只显示一行灰色「自动继续 · 第 n/6 轮」，不冒充用户发言），完成后 `update_goal status="done"` 立刻停止，卡住时用 `status="blocked"` 写清原因。为防一直轮询：单次目标最多 6 轮、连续两轮没有任何目标/计划更新会自行停止、用户点停止或关掉「自动推进」也立即停止；暂停/受阻后可在目标卡片里继续。目标和计划随会话保存，重启后仍在。新聊天时「⋯」右侧还有一个隐私图标：点开后这条聊天成为临时聊天，标题后出现灰色「临时聊天」；会话一旦开始，图标消失，灰字保留。临时聊天不写入会话和图片、不提取记忆，也不注入已有记忆。浏览器版和未配置密钥的桌面版仍是模拟模式。

Mova 的 HTML 界面原型。默认显示 ChatMova，支持切换 CodeMova。对话输入区使用 LeiBox 发布的 React Deep Agent Composer。

## 运行

在项目目录安装依赖并构建、启动 Windows 桌面版：

```powershell
npm install
npm run desktop
```

需要 **Docker Desktop**（本机服务版）。首次启动可能需要下载 Electron 和本地 Embedding 模型；Docker 镜像、模型和数据库只在本机。桌面版从本地构建产物加载，无需启动 Vite。当前提供开发启动命令，尚无安装包。

在「设置 → 模型」中可添加多个模型提供商，分别填写显示名称、API 地址、API 协议（OpenAI Chat Completions 或 Anthropic Messages）和 API 密钥：保存后点「获取可用模型」读取该提供商的模型列表，勾选要保留的模型，并可逐个调整「多模态」能力和思考强度档位（档位随模型列表自动识别，也可以手动改）。每个提供商会显示是否已保存密钥，编辑器里的「当前聊天模型」可直接切换聊天使用的模型。密钥由桌面后台使用 Windows 系统加密保存，`providers.json` 只保存地址、协议和模型目录。

模型请求按当前选中的提供商和模型发出；默认的「本地网关」仍指向 `http://127.0.0.1:8788/v1`，需要本机服务保持运行。模型能否使用取决于提供商密钥的权限和出口设置。搜索源的密钥与开关也在同一页配置。

在输入框的模型菜单切换当前模型；「思考强度」直接使用当前模型声明的等级——模型声明几档就显示几档（例如 `low/medium/high/max` 四档，或 `high/xhigh` 两档），没有思考能力的模型不显示这一行。联网搜索默认开启：只要有一个搜索源可用（AnySearch、Tavily 或自托管 SearXNG），模型就能按需检索。检索走 `electron/search/` 的管线：多查询并发 → RRF 融合去重 → 权威度/时效打分 → 读正文并按问题选段 → 打包成带 `[n]` 编号的证据块，模型再用 `[n]` 引用来源。搜索设置页可选检索深度（快速/标准/深入）、区域与语言，逐源启用与测试。单轮检索有配额（默认 12 个查询 / 8 次读页 / 12 万字符 / 60 秒），用尽时如实告知已获得的证据而不是静默失败。模型会接收当前会话的文本、近期图片以及长对话的有限摘录；长期记忆不会在每轮开始前自动检索或注入，而由模型在确有需要时调用工具获取。预置示例和模拟助手回复不会作为上下文发送。模型会接收当前会话的文本、近期图片以及长对话的有限摘录；长期记忆不会在每轮开始前自动检索或注入，而由模型在确有需要时调用工具获取。预置示例和模拟助手回复不会作为上下文发送。

## 联网搜索（检索管线）

模型侧只有三个工具，语义与预算都可控：

| 工具 | 用途 | 关键行为 |
| --- | --- | --- |
| `web_search` | 一般/垂直检索 | 一次可发 2–4 条互补查询（≤5 条、每条 ≤400 字）；可选 `tag` 走垂直索引（`code.snippet` / `academic.paper` / `finance.quote`）与 `params`；返回带 `[n]` 编号的证据块，末尾附「检索说明」 |
| `web_read` | 读某一页正文 | 走搜索源的正文抽取接口，按 `question` 只回传相关段落（默认 ≤8000 字） |
| `web_research` | 广问题一次搞定 | 多查询 + 自动读前 N 页 + 附「补搜建议」（未覆盖的问题角度），同样支持 `tag` |
| `verify_citations` | 引用自检 | 校验答案里的 `[n]` 是否存在、被引句子能否在对应段落定位 |

垂直索引会按问题**自动选择**（代码类 → 代码索引，论文类 → 论文索引，行情类 → 财经索引），模型也可以显式指定；垂直索引返回空时会自动退回通用搜索并说明。

管线（`electron/search/`）：`providers/*` 适配器（多源可插拔、逐源降级）→ `fuse.cjs` RRF 融合与 canonical 去重 → `score.cjs` 权威度/时效加权 + 同域 2 席 → `passage.cjs` 段落切分与选段（有本地 e5 向量时用向量，否则关键词）→ `pack.cjs` 证据块 → `citation.cjs` 引用校验。配置写在 `userData/search-config.json`（深度、区域、语言、逐源开关与该源密钥的加密文件）。

两个逃生口：
- `MOVA_SEARCH_MODE=legacy` 一键退回旧的「单查询 × 5 条摘要」行为；
- `MOVA_SEARCH_VECTOR=0` 关闭本地向量选段（本地模型未缓存时也会自动退回关键词，不会中途下载模型）。

已知限制：`[n]` 的编号是「每一次工具调用内」的编号；`verify_citations` 会在所有已发生的调用里找匹配项，所以跨多次搜索时编号可能指向不同的同序号来源，此时只提示引用风险，不会中断回答。

验收：`node --test tests/search-*.test.mjs`（含 60 条 golden 用例：命中域名、`[n]` 可回溯、无来源时拒答），`npx tsc --noEmit`，`npm run build`。

## 本机服务版：PostgreSQL、pgvector 与记忆

桌面版现在默认使用**本机 Docker 服务**：

- PostgreSQL 16 + pgvector：会话、记忆、搜索分块向量；
- Redis + BullMQ：后台索引、备份和会话同步任务；
- MinIO：图片持久化时本地 + S3 镜像，读取时本地优先、S3 回退；
- 本地 ONNX Embedding：`Xenova/multilingual-e5-small`，384 维，不依赖 Python/Ollama。

安装 Docker Desktop 后，直接运行 `npm run desktop`。Electron 会调用 `scripts/services.mjs ensure`，自动启动 Docker Desktop（如果尚未运行）和三个容器，并执行数据库迁移；不需要手动 `docker compose up`。也可以单独执行：

```powershell
npm run services        # 启动/检查本机服务并迁移
npm run services:status # 查看数据库、Redis、MinIO 健康状态
npm run db:migrate      # 手动执行迁移
node scripts/pitr.mjs status       # WAL 归档/基础备份/PITR 能力
node scripts/pitr.mjs base-backup  # 物理基础备份
node scripts/pitr.mjs list         # 基础备份列表
```

服务只绑定 `127.0.0.1`：PostgreSQL `55432`、Redis `56379`、MinIO `59090`（控制台 `59091`）。Windows 可能保留 58986–59085 端口，因此 MinIO 使用 59090，不能随意改回 59000。

会话和长期记忆写入 PostgreSQL，不再以 JSON 为权威来源。`MOVA_MODE=local` 时才会回退到旧的 `userData/memory/repository.json` 本地仓库；服务版首次启动从空数据库开始（本次按“直接重建”处理，旧 JSON 不会自动导入）。设置页显示实际连接目标，不会显示数据库密码。

自动记忆只从**用户自己的消息**中提取，由当前聊天模型判断哪些事实、偏好和决定值得跨对话保留；不会把 AI 回复、工具输出或演示内容写成用户事实。发送给模型前会遮盖密码、密钥、令牌等疑似凭据，写入前还会再过滤一次。默认不再使用本地规则提取：LLM 不可用、超时、限流或返回非法结果时，这条记忆会明确标记失败，不会静默回退到正则规则。CodeMova 中提取的记忆限定在来源项目；ChatMova 没有项目范围，提取结果保存为全局记忆。项目记忆不会离开所属项目，跨项目信息需要显式写成全局记忆。

「设置 → 记忆与存储」提供：

- 长期记忆总开关、自动提取开关、是否在项目中使用全局记忆。
- 每次记忆搜索返回的条数上限、字符上限，以及记忆总条数上限。
- 按当前项目或全局查看记忆，手动添加、编辑、置顶、停用、启用、删除，并跳转到原始消息来源。
- 关键词 + 向量混合检索（RRF，默认各 0.5），可限定当前项目、全局或由你主动选择「全部项目」；结果标明项目并可直接打开原会话、原消息。Agent 搜索不会跨项目，是否包含全局记忆由设置控制。
- 服务连接与健康状态、自动备份与恢复、Embedding/索引状态、语义检索开关与权重、记忆提取模式、存储配额与服务状态。
- 提取任务持久化在 `mova_memory_jobs`；设置页显示最近任务状态、尝试次数和失败原因，应用重启后会恢复未完成任务。
- 不在每轮回答前自动搜索记忆；启用长期记忆时，模型可按需在同一轮内多次调用 `memory_search`，搜索过程显示在对话时间线。关闭后不提供该工具，已开始的工具调用也会复查开关。记忆提取是独立流程，不等于回答前检索。
- 密码、API Key、Bearer、私钥、身份证、银行卡在发送模型和写入任务前分段遮盖；不再因为一条消息里出现敏感词就丢掉整条合法记忆。
- 「隐私保险库」使用主密码 + scrypt + AES-256-GCM 加密保存密码、API Key、Token 和私密备注；主密码不落库，保险库随数据库备份时只包含密文。
- 「记忆维护与压缩」会归档过期/低价值记忆、合并完全重复项；置顶和高重要性记忆不会被归档。
- 支持“忘记 1887”“把 1887 改成 1888”“以后不要再记关于 X”等自然语言管理命令；多个匹配时只返回候选，不静默批量删除。
- 手动导出未加密备份；逻辑 `pg_dump` 备份已启用 WAL 归档，`scripts/pitr.mjs` 可把基础备份 + WAL 恢复到**新集群**，不会覆盖当前库。服务版设置页默认拒绝覆盖当前数据库：无法保证其他进程及外部数据库连接已停止写入，不能仅凭确认词安全恢复。
- 历史默认永久保留；临时聊天不写入存储，也不会读取或提取记忆。
- 图片持久化时同时写入本地并镜像到 MinIO；上传失败不会阻止本地图片。配额上限可在设置页填写，数据库/附件写入前检查。

当前明确的边界：没有官方 Pi `SessionManager`（安装的 Pi SDK 不提供，使用兼容的事件存储层），也没有 Dot 前端、Worker 或任务恢复。PITR 通过 CLI 恢复到新集群，设置页不提供时间点选择；附件备份/异地归档尚未实现。

## CodeMova：项目文件权限

CodeMova 可以真实读写项目文件、执行命令。文件读写被限制在**你显式授权的文件夹内**；`exec` 则**不是沙箱**——它用你的用户权限启动普通 shell，能访问项目之外的文件和网络。完整模型见 [Mova权限设计.md](docs/plans/Mova权限设计.md)。

- 三种能力按文件夹独立授予：`read`（列出、读取、搜索、Git 只读）、`write`（新建、覆盖、精确替换、撤销）、`exec`（运行命令）。默认全部关闭；`write` 依赖 `read`，撤销 `read` 会连带撤销 `write`。
- 添加项目文件夹只做**登记**，不授予访问权；开启能力必须经过原生系统对话框，对话框会显示完整路径。渲染层发起的登记同样要原生确认。
- 单次写入 / 命令的审批在应用内完成（输入框上方的审批条），不再弹系统模态框；系统对话框只用于授予能力。审批条属于应用内提示：被攻破的渲染层可以伪造它，真正的安全边界是授予能力时的原生对话框。
- 输入栏里的「请求批准」是**审批级别**，三档，选中即写入主进程的权限存储：**请求批准**（默认，修改文件与运行命令每次都问）、**替我审批**（修改文件不再逐次询问，运行命令仍会询问）、**完全访问权限**（两者都不再询问；选中时先弹一次原生确认）。「完全访问权限」还会把本轮范围放大到**所有已登记的项目文件夹**（不再限于当前项目），并按 `read/write/exec` 全开执行，命令本身不受路径护栏约束；「请求批准 / 替我审批」仍只在当前项目的已授权文件夹内操作。未登记的磁盘路径依然不能通过文件工具访问（shell 命令可以，它本来就不是沙箱）。
- **取消**：点停止会中止请求、立即关掉待批的审批条，并让工具在授权返回后、以及真正落盘前（路径锁内）各检查一次中止状态；`run_command` 会杀掉整个进程树。
- 所有**文件工具**的路径必须在项目文件夹内：拒绝绝对路径、`..`、盘符、UNC、NTFS 备用数据流（`a.txt:stream`）、Windows 设备名（`CON`/`NUL.txt`）和段尾的点或空格，并用 `realpath` 拦截 junction / 符号链接逃逸；`.git` 内部文件禁止写入。这是"检查后打开"的防护，不是 OS 沙箱，理论上仍有符号链接竞态；`run_command` 完全不受这些路径护栏约束。
- `run_command` 有两种写法：`command` 是一整行，交给 shell（Windows 为 `cmd.exe /d /s /c`）解释；`argv` 是 `[程序, ...参数]`，以 `shell: false` 直接启动，参数原样到达进程，内联脚本（`["node", "-e", "…"]`）不再受嵌套引号折磨。`command` 行的引号现在会原样交给 cmd——Node 过去按 C 运行时规则重新加引号，`node -e "console.log(2+2)"` 到 node 手里就是一段破碎脚本（退出码 0、stdout 空）；外层再包一对引号后，以引号开头的行（如 `"C:\Program Files\nodejs\node.exe" -e "…"`）也不再丢首引号。cmd 内置命令与 `.cmd`/`.bat` 仍要用 `command`。输出先按 UTF-8 解，失败时按控制台代码页（`chcp`，中文系统 936 → GBK）转成 UTF-8，结果的 `encoding` 说明用了哪种；每条流只回 8000 字符（开头 + 结尾，中间标注省略，`truncated: true`），长输出请重定向到文件再 `read_file`。`command` 上限 2000 字符、`argv` 合计 16000 字符，超限返回 `command-too-long` 并给出改法，而不是一句笼统的 schema 校验错误。
- 撤销立即生效：每次工具调用都会重新读权限存储，写入 / 命令在路径锁内还会再核对一次，所以审批期间被撤销的能力不会生效。
- 模型只在授权后看到对应工具；未授权时系统提示仍是"不能访问本地文件、终端或电脑"，不会凭空声称改过文件。
- 单轮**没有**工具调用 / 写入 / 命令的次数上限：一个"读→改→跑测试→再改"的长任务可以一直做下去，直到模型自己停下、你点停止，或输出预算耗尽。保留的只有输出预算（工具结果单条 40k 字符、单轮 200k 字符，与文本流共用 1MB 总输出），因为那是模型上下文而不是策略——超了就是下一次请求直接报错。
- `write_file` / `replace_in_file` 在路径锁内完成"比对审批时的内容 → 写入 → 记录撤销条目"，审批期间文件被改动会返回 `conflict` 而不是覆盖；`undo_change` 可按 `changeId` 撤销，`list_changes` 列出最近修改，历史在 `userData/file-history/`（明文，仅本机）。撤销记录在写入之后落盘：进程若在两者之间崩溃，这次修改就无法撤销。
- 读取：文本 ≤4 MB 整份读，更大的文件按行范围**流式**读取（不再有 4 MB 墙，超过 512 MB 才拒绝）；二进制文件不再报错——返回 `mime`、字节数、前 4 KB 的 base64 和最多 40 条可打印片段，能认出图片、PDF、压缩包和可执行文件。二进制不能被写入覆盖（没有可撤销的文本快照），要替换先删除。
- 删除、移动、批量改：`delete_path`（单文件可撤销；文件夹需 `recursive`，且只接受 ≤50 个文件、合计 ≤2 MB、非二进制、内部无 `.git`，每个文件单独记撤销）、`move_path`（同一项目文件夹内；文件移动可撤销，文件夹移动不可撤销）、`apply_changes`（一次审批改多个文件，先全部校验再全部写入，失败回滚已写文件并报 `rollbackFailed`）。`project_tree` 给一份有界目录树快照，`find_symbol` 用字面量找定义与引用。
- 每次允许、拒绝、授权、撤销写入 `userData/permissions-audit.jsonl`。

限制：审批条只显示**这一次**请求的 diff，历史 diff 暂时没有界面入口（主进程仍写在 `userData/file-history/`）；没有 Git 写入（`git_status`/`git_diff` 只读）；命令能访问网络且不受路径护栏约束；`apply_changes` 的"全写或全不写"只在进程存活时成立——崩溃可能只写了一半，回滚是尽力而为。

当前版本**没有权限设置界面**：项目文件夹在新建项目时登记，登记只保存路径、不授予访问；单次写入 / 命令在输入框上方的审批条里确认，审批级别用输入框左侧的「请求批准 / 替我审批 / 完全访问权限」三档切换。逐文件夹的读取 / 修改 / 执行授权与撤销仍由主进程的权限存储和原生确认完成，渲染层暂时没有对应入口。移除项目时，属于它且没有其他项目引用的文件夹会被一并清除授权——重新登记一个已授权的文件夹会先确认是否保留旧授权，避免"删项目再建项目"绕过扩权确认。

审批条用行级 diff（旧/新两列行号、绿加红删、保留空白可复制）：主进程每侧最多发送 300 行 / 100k 字符，超出会标注「只发送了预览片段」；面板默认显示 300 行，超出给「显示全部」。批量请求按文件折叠，顶部汇总 `N 个文件 · +X −Y`；单侧超过 200k 字符不计算 diff，退回全文对照并说明。点 diff 行复制 `path:行号`。

「改动历史」面板的代码仍在 `src/features/changes/`，但入口随权限设置界面一起移除，目前打不开：它列出最近的写入/替换/删除/移动/撤销（只读、不回传内容摘要），点开用同一套 diff 渲染，并能「在资源管理器中显示」——路径先在主进程用同一套护栏校验，越界直接返回 `path-escape`，不接受渲染层传来的绝对路径。审批条里的「在资源管理器中显示」只在请求带 `rootId` 且能确定根内相对路径时出现，不会靠显示名反查文件夹。

项目可以保存一段**自定义指令**（项目菜单 → 编辑），它会注入该项目 CodeMova 对话的系统提示，用来放构建命令、包管理器、不要动的文件这类约定。

### 打包 Windows 便携版

```powershell
npm run package:desktop        # release/Mova-win32-x64/
npm run package:desktop:zip    # 同上，并压成 release/Mova-<version>-win32-x64-portable.zip
```

产物是一个自包含目录：复制过去、双击 `Mova.exe` 即可运行，目标机器不需要 Node.js 或本仓库。目录结构：

- `Mova.exe` + Chromium 运行时（`electron/dist` 的原样拷贝，只保留 `en-US`/`zh-CN`/`zh-TW` 语言包）
- `resources/app/`：`package.json`、`dist/`（Vite 产物）、`electron/`（主进程，不含测试）、`assets/`、`scripts/services.mjs`、`scripts/db-migrate.mjs`、`docker-compose.yml`
- `resources/app/` 里额外带上主进程**跨目录引用**的模块：`src/features/chat/context-budget.mjs`（`electron/chat-agent.mjs` 引用）和 `edge-extension/pointer.js`（`electron/browser/{controller,target}.cjs` 引用）。这两个文件由脚本扫描 import 自动补齐，不是手写清单
- `resources/app/node_modules/`：只放主进程真正 `require` 的运行时依赖（`pg`、`sharp`、`koffi`、`ioredis`、`bullmq`、`@aws-sdk/client-s3`、`@huggingface/transformers`、`@earendil-works/pi-*`、`yaml`、`undici` 及其传递依赖），按平台裁掉 `onnxruntime-node` 的 darwin/linux/arm64 二进制，跳过只给浏览器用的 `onnxruntime-web`
- `README.txt`（给使用者看的启动 / 数据目录 / 本地服务说明）、`repair-and-start.cmd`（解压后补目录权限再启动）

主进程不是一棵自包含的目录树：`electron/` 里的模块会跨出去 import（`../src/...`、`../../edge-extension/...`）。脚本按 import 关系做闭包拷贝，然后在收尾时**静态校验整个包**：每个相对 import 必须在包内解析得到，每个裸包名必须在 `resources/app/node_modules` 里存在，否则直接让打包失败。这一层是必需的——这类缺失只在功能第一次被用到时才炸（例如 `chat-agent.mjs` 是发消息时才 `await import()` 的，窗口能正常打开、日志也没有报错），光靠启动冒烟测不出来。

`scripts/package-desktop.mjs` 会顺带给产物目录授予 `ALL APPLICATION PACKAGES` 读取权限——Electron 在 Windows 上的子进程用 AppContainer 令牌，缺这条授权会在 `main.cjs` 运行前以 `0x80000003` 崩溃（与 `scripts/prepare-electron.mjs` 同一个原因）。zip 不保存 ACL，所以解压出来的副本会丢掉这条授权：`repair-and-start.cmd` 就是给使用者补这一步的入口（已有授权时直接启动，递归授权 16000 多个文件大约 40 秒）。该批处理保持纯 ASCII：在批处理中途 `chcp 65001` 再加上多字节文本会让 cmd.exe 解析错位，实测表现为整段不执行、退出码 0。

注意：在设置了 `ELECTRON_RUN_AS_NODE=1` 的终端里直接启动 `Mova.exe`，Electron 会退化成 Node 解释器，进程 100ms 内以退出码 0 结束、不建窗口也不写日志。从资源管理器双击不受影响；命令行启动前先 `Remove-Item Env:ELECTRON_RUN_AS_NODE`。

## 目标与计划、Token 用量（agent 侧）

**目标与计划是真实能力，不是展示层。** 每次模型请求都会带上三个工具，模型自己决定何时使用：

| 工具 | 作用 |
| --- | --- |
| `set_goal` | 创建或替换本条会话唯一的目标（标题 + 可选说明），状态置为进行中 |
| `update_goal` | 改目标状态：`active` / `paused` / `done`。提示词要求「真的做完并核对过」才可置 done |
| `set_plan` | 写入有序步骤清单（1–12 条，`pending` / `active` / `done`，可带一句进度说明）。每次发送完整清单，只允许一个步骤处于 `active` |

工具写入后立即通过 `model:delta` 推送 `goal` / `plan` 事件，渲染层只渲染这些工具真正写过的内容，绝不根据对话正文猜测进度。数据按会话保存在本地工作区快照（`aims`），随会话删除一并清理，临时会话永不写入。

**Token 用量同样是真实数据。** `electron/chat-agent.mjs` 在每次 `message_end` 读取提供商返回的 `usage`（input / output / cacheRead / cacheWrite / totalTokens / cost），累计后推送 `usage` 事件；渲染层把每次调用累加进该会话的用量记录（`usage` 字段），并记录模型调用次数与最近一轮墙钟耗时。拿不到的值一律显示为「—」「未上报」或「未配置价格」。

事件通道说明：`usage` / `goal` / `plan` 属于会话级状态，与 transcript 行（`text` / `thinking` / `tool` / `search` 等）分成两条通道（`StateEvent` 与 `ReplyEvent`），不会混进消息列表。
## 原型边界

菜单栏、语音和用量仍以外观演示为主。桌面端的 CodeMova 可以在**已授权**的项目文件夹内读取、修改文件并运行命令（见上文「CodeMova：项目文件权限」）；未授权时模型看不到这些工具，界面也会如实说明。浏览器版不提供文件访问。截图中的项目和聊天文字是设计样例。输入草稿和 MovaBot 会话仍仅保存在页面内存中。

长期记忆已接入本机 PostgreSQL + pgvector、本地 Embedding、关键词/向量混合检索、Redis/BullMQ 索引任务、逻辑备份/恢复、WAL 归档/PITR CLI、MinIO 图片镜像、配额检查和兼容事件存储；`MOVA_MODE=local` 才会回退到旧的本地 JSON。仍未实现官方 Pi `SessionManager`、附件备份/异地归档和 Dot 的任何功能。服务版不是多用户/团队版本；数据库权限按单用户 owner 运行。
