> 结论先行：**Gemini 订阅通道（ACP）已 100% 走技能包**；**API Key 通道（pi-ai）只切了 4 个行为等价的包**，
> 搜索 / 浏览器 / 桌面 / 画板这 4 类仍是 `chat-agent.mjs` 里的手写实现。两条链路共用同一个装配函数

> 这份文档记录「为什么停在这里」与「要继续推进必须先补什么」，避免下一个人从零重新论证一遍。

## 2. 为什么没有一刀切

四个能力族切到技能包会**付功能或体验代价**，而技能包当时不允许改（另一批子智能体正在写它们），
证据不足以下刀：

1. **联网**：`web-research` 包是瘦身版——没有单轮预算记账、没有垂直索引路由（代码片段 / 学术论文 / 行情）、
   没有 AnySearch legacy 模式。切过去等于悄悄删功能，还会连带删掉 4 个既有测试。
2. **内置浏览器（Edge 专属会话）**：manifest 的 `browser_wait` 枚举固定包含 `download` / `time`，
   而 Edge 扩展通道不支持这两个条件；切过去模型会调用不存在的等待条件
   （`tests/browser-prompt-contract.test.mjs` 正是守这条合同）。
3. **桌面**：桌面包给每个 `desktop_act` / `desktop_batch` / `desktop_app` / `desktop_skill` 都加了 exec 审批，
   而桌面引擎自己的策略是 R1/R2 免问、R3 才问。切过去等于**每次点一下鼠标都弹一张卡**。
4. **画板**：画板包给 `design_apply` / `design_undo` 加人工审批，而画板现有的口径是
   「AI 编辑」开关 + 每条 command 复查。切过去每次改画布都多一张卡。

## 3. 要继续推进，先补这些（按值得做的顺序）

1. **给 `web-research` 补回搜索能力**（预算记账 / 垂直路由 / legacy 模式），然后才谈 pi-ai 切换。
   这是四类里唯一「切过去只是缺功能、不会破坏体验」的，补完就能收。
2. **浏览器**：让 `browser_wait` 的等待条件按通道能力裁剪（manifest 支持「按依赖声明可用的枚举」），
   或在 Edge 通道上让技能层拒绝 `download` / `time` 并给出可读错误。之后才能切。
3. **桌面**：让 `desktop-control` 的 `approval.mode` 与桌面策略 R1/R2/R3 对齐（低风险动作 `mode:'none'`，
   只让 R3 走 `policy`），并让技能层成为**唯一**审批入口（`desktop_act` 双弹审批已修，但只在引擎对象形态下生效；
   生产接线现在把 `deps.desktop` 传成**数组**，那条路上仍会双弹 —— 需要接线改成「引擎对象 + `desktopApprove`」）。
4. **画板**：把「AI 编辑开关」翻译成 `approval.allowSession` 语义，避免每次改画布多一张卡。

## 4. 其它已知债务（与技能化直接相关）

- `context-ledger` / `goal-plan` / `memory` / `web-research` 四个包里仍各有一份形态不同的入参校验
  （`check()` / `checkSteps()` / inline 判断），尚未并到 `electron/skills/input-schema.mjs`。
  四个大包（project-fs / browser / desktop / design）已经并过去了（共删掉 266 行重复实现）。
- `browser_batch` 若多步都带 `observe: true`，各步快照都按 24 000 字符独立预算，正文可能超过声明的
  `maxResultChars: 24000`，超出部分靠截断说明兜底。
- `permissions.net` 至今**没有任何代码复查**：联网类工具实际只由人工审批把关。技能化把更多联网能力
  （浏览器、web-research）搬进了统一通道，这条缺口因此更值得补。
- `electron/skills/README.md`、`packs/README.md` 与方案 §2.2 的 `SkillToolDef` 表还没写 `maxResultChars`
  （实现已生效，文档待补）。
