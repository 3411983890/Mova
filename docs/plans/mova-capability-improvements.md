# Mova 桌面端能力与记忆系统改进规划

> 本文档整理自对 Mova 桌面端现有工具链（`memory`、`browser-automation`、`design-canvas`、`desktop-control`、`project-fs`、`goal-plan` 及右侧栏文件预览）的实际使用体验与改进构想，涵盖**已有能力优化**与**新功能规划**，并按优先级给出落地建议与验收标准。

---

## 一、核心痛点与总体目标

目前 Mova 已经具备较完整的本地能力底座，例如：
- **安全可控的设计**：无障碍树 diff 观察（`browser_snapshot`）、敏感凭据不进模型上下文（`browser_login`）、文件写入/修改走审批与可撤销机制（`mova_write_file` / `mova_apply_patch`）。
- **多模态与多视图协同**：内置侧边浏览器、设计画板、右侧栏文件预览（代码 / Markdown）。
- **跨会话连续性**：长期记忆读写（`mova_memory_write`、`mova_memory_search`）、原文回查（`memory_read_source`）与上下文自动注入（`【相关记忆】`）。

在此基础上，下一步的核心优化目标为：
1. **让记忆“可演进、可治理”**：从“只增不减”升级为全生命周期管理，避免过时信息干扰判断。
2. **降低高频工具的调用开销**：减少“先查 schema 再调用”的两跳延迟与上下文浪费。
3. **打通右侧栏各视图的联动**：让浏览器、设计画板、文件预览与对话之间的数据流转更顺畅。

## 二、长期记忆系统（`memory`）改进与新功能

### 2.1 已有功能改进

#### 1. 增加记忆的「更新 / 替代 / 归档」能力（解决只增不减问题）
- **现状与痛点**：目前仅提供 `mova_memory_write` 新增写入，缺少修改、覆盖或废弃旧记忆的接口。当项目进度推进（如“正在开发”→“已完成”）或技术选型变化时，旧记忆与新记忆会同时存在，导致检索或自动注入产生冲突。
- **改进方案**：
  - 新增 `memory_update` / `memory_supersede`：支持按记忆 ID 更新内容，或用新记忆替代旧记忆（保留历史版本链，标记旧条目为 `superseded`）。
  - 新增 `memory_archive`（软删除/归档）：允许模型（经用户审批）或用户手动将过时、错误记忆移出活跃检索集。
  - **写入去重与合并提示**：调用 `mova_memory_write` 时，若语义检索到高相似度已有条目，自动提示“覆盖更新”或“合并”而非直接新增重复条目。

#### 2. 扩展 `mova_memory_search` 的检索过滤维度
- **现状与痛点**：目前仅支持 `query`、`scope`（`current` / `global`）、`source`（`auto` / `memory` / `history`）和 `limit`，在记忆条目增多后难以精确筛选。
- **改进方案**：
  - 增加 **`kind` 过滤**：支持按 `fact` / `preference` / `decision` / `note` 过滤。
  - 增加 **时间范围过滤（`timeRange` / `after` / `before`）**：便于只检索近期决策或特定阶段的对话历史。
  - 增加 **来源类型区分**：区分模型/用户主动写入的确定性记忆与系统自动提取的记忆（`automatic`），支持按权重排序。
  - 增加 **项目维度精确过滤**：在多项目工作区场景下，支持按指定项目根目录过滤记忆。

#### 3. 提升上下文自动注入（`【相关记忆】`）的透明度与可控性
- **现状与痛点**：对话开始时自动注入的 `【相关记忆】` 目前只展示文本和 `(automatic)` 标记，缺少 ID、写入时间及关联项目，且无法在当前会话中快速纠偏或屏蔽。
- **改进方案**：
  - 每条注入记忆附带 **短 ID 与更新时间**，方便模型判断时效性，或直接引用 ID 调用 `memory_read_source` / `memory_update`。
  - 支持用户对注入的某条记忆进行 **一键屏蔽 / 标记过时**，防止错误记忆在后续对话反复出现。

### 2.2 记忆系统新功能规划

#### 1. 记忆可视化管理面板（UI 层）
- 在桌面端提供独立的「记忆管理」视图或侧边抽屉，支持：
  - 按项目 / 全局、分类（`fact` / `preference` / `decision` / `note`）、写入来源（手动 / 自动）筛选与搜索。
  - 直接查看、编辑、归档或删除单条记忆，以及查看其关联的原始对话片段。
  - 支持记忆的导入/导出（Markdown / JSON 备份）。

#### 2. 会话阶段性摘要与自动沉淀（Session Digest）
- 在长对话结束或用户切换任务时，自动生成一份结构化的会话摘要候选（包含：核心决策、变更文件、遗留 TODO），由用户一键确认后批量沉淀为长期记忆，减少零散碎片记忆的产生。

#### 3. 记忆生命周期与过期（TTL）机制
- 为不同 `kind` 或场景的记忆提供可选的有效期或“活跃度衰减”机制：
  - `preference`（用户偏好）与 `decision`（架构决策）默认长期有效。
  - 临时任务状态（如“当前正在调试某 bug”）支持设置短期 TTL 或在对应目标完成后自动提示归档。

## 三、工具调用效率与开发者体验（DX）优化

### 3.1 降低高频按需工具的“两跳”调用成本
- **现状与痛点**：目前大量高频本地能力（如 `browser_navigate`、`browser_snapshot`、`browser_act`、`design_open`、`design_read` 等）属于按需技能，新会话中往往需要先调用 `mova_skill_search` 查 schema，再调用 `mova_skill_call` 执行，额外消耗轮次、延迟与上下文 token。
- **改进方案**：
  1. **轻量参数签名内联**：`mova_skill_search` 默认返回结果中直接附带精简的参数签名（必填字段与简短类型说明），常规调用无需再传 `includeSchema: true` 查完整 JSON Schema。
  2. **按场景动态置顶工具（Tool Pinning）**：当用户开启了右侧浏览器、设计画板或处于某类任务中时，自动将对应技能组的核心工具（如 `browser_navigate` / `browser_snapshot` / `design_open`）直接暴露到当轮可用工具列表，免去搜索步骤。

### 3.2 批量与组合操作增强
- 鼓励和完善类似 `browser_batch` 的复合调用模式，针对文件读取、代码检索等高频只读操作，支持一次调用批量读取多个小文件或目录摘要，进一步减少往返轮次。

## 四、内置浏览器（`browser-automation`）增强

1. **站点技能（Recipe）的可视化管理与录制**
   - `browser_batch` 已支持重放已保存的站点技能（`recipe`），建议在 UI 上增加「站点脚本/Recipe 管理」入口，支持查看已录制步骤、编辑参数、一键回放与分享。
2. **本地页面预览热更新联动**
   - 当使用 `browser_navigate` 打开项目内的本地 HTML/SVG（`file:///`）并在对话中持续修改该文件时，支持自动刷新或提示刷新右侧浏览器视图，形成“编辑 → 实时预览”闭环。
3. **下载与弹窗状态的更清晰反馈**
   - 强化 `browser_wait` 对文件下载完成、新标签页打开及 iframe 嵌套场景的可观测性，返回明确的下载文件路径与状态。

---

## 五、设计画板（`design-canvas`）与右侧栏文件预览联动

1. **画板与项目文件的双向协同**
   - 支持将设计画板中的页面/组件结构（通过 `design_read` 获取）一键导出或同步为项目内的 HTML/CSS/设计规范 Markdown 文档。
   - 支持将 `browser_screenshot` 截取的网页参考图直接发送到设计画板作为参考底图。
2. **右侧栏文件预览（代码 / Markdown）增强**
   - **大纲与行号定位**：Markdown 预览支持目录大纲折叠与跳转；代码预览支持符号定位，并与对话中 `file:///path#L10-L20` 链接点击直接联动定位到指定行。
   - **差异对比预览模式**：在模型通过 `mova_apply_patch` / `mova_write_file` 修改文件后，支持在右侧栏直接切换“渲染预览 / 源码 / Diff 对比”三种视图。

---

## 六、目标计划（`goal-plan`）与长任务连续性

1. **计划状态与长期记忆联动**
   - 当 `mova_set_plan` 中的关键步骤全部变为 `done` 时，自动生成完成总结并提示更新或归档相关的“进行中”记忆，避免状态脱节。
2. **跨会话任务恢复**
   - 支持将未完成的 `goal` 与 `plan` 持久化到项目级状态中，下次打开同一项目时可一键恢复上下文继续执行。

---

## 七、落地优先级路线图（Roadmap）

| 优先级 | 模块 | 改进项 | 预期收益 | 验收标准 |
| :--- | :--- | :--- | :--- | :--- |
| **P0** | 记忆系统 | `memory_update` / `memory_supersede` / `memory_archive` 接口与去重提示 | 解决过时记忆冲突，提升记忆准确率 | 能够通过工具更新/归档指定 ID 记忆；归档后不再出现在默认检索与自动注入中 |
| **P0** | 工具效率 | `mova_skill_search` 默认附带精简参数签名 / 高频工具按场景直出 | 减少 30%~50% 的工具发现轮次与延迟 | 常见浏览器/画板/记忆回查操作可在单次搜索后直接调用，无需二次查完整 schema |
| **P1** | 记忆系统 | `mova_memory_search` 增加 `kind` 与时间范围过滤；`【相关记忆】`附带 ID 与时间 | 提升复杂项目下的记忆召回精度 | 支持按分类和时间区间过滤；上下文注入条目可追溯来源 ID |
| **P1** | 文件预览 & 浏览器 | 右侧栏文件预览支持 `#L行号` 精确跳转；本地 HTML 修改后浏览器联动刷新 | 提升代码/文档阅读与前端调试流畅度 | 点击对话中的带行号文件链接可在右侧栏高亮定位到对应行 |
| **P2** | 记忆系统 | 记忆可视化管理面板 & 会话摘要自动沉淀 | 降低用户管理记忆的心智负担 | 用户可在 UI 中独立增删改查、筛选与导出长期记忆 |
| **P2** | 生态联动 | 浏览器截图直达画板、Recipe 管理 UI、跨会话 Goal/Plan 恢复 | 打通“浏览 → 设计 → 编码 → 验证”全链路 | 长任务中断重开后可恢复计划进度，各右侧栏视图间支持一键流转 |
